# Detecting transportation mode from smartphone sensors

> a 14-feature subset recovers essentially all the accuracy the full 36 features ever offered, and that same redundant, non-Gaussian structure is why every tree-based method beats every linear method by 25 to 30 percentage points.

## Abstract and introduction

This page documents a two-person final project for STAT 385 at UIC, with Michelle Segura, asking two connected questions about the TMD (Transportation Mode Detection) dataset of Carpineti, Lomonaco, Bedogni, Di Felice, and Bononi (2018): which of 36 sensor-derived features actually carry independent information about a smartphone user's mode of transportation (walking, driving a car, riding a bus, riding a train, or standing still), and which machine learning method classifies that mode best. The dataset's third and most complete version, \(D_3\), gives 36 features derived from nine sensors, accelerometer, gyroscope, gyroscope uncalibrated, linear acceleration, orientation, rotation vector, game rotation vector, sound, and speed, each summarized by its mean, minimum, maximum, and standard deviation over a five-second window.

Six independent feature-selection methods (ANOVA, PCA, multinomial LASSO, Boruta, recursive feature elimination, and conditional permutation importance) converge on the same answer to the first question: the 36 raw features are substantially redundant rather than individually useless, and a 14-feature subset recovers essentially all achievable accuracy. That same redundant, non-Gaussian structure explains the second question's answer: comparing nine modeling approaches on an identical training and test split, every tree-based method outperforms every linear method by 25 to 30 percentage points, with a correctly-tuned XGBoost model reaching the best accuracy of any method attempted, 97.29%. A third, exploratory line of investigation, using unsupervised clustering, shows that the persistent confusion between Bus, Car, and Train reflects genuine geometric closeness of these three classes in sensor space, not a weakness of any one classifier.

## Data

\(D_3\) contains 5,893 observations across 36 sensor features, a time field, and the target class label, split 4,714 training rows to 1,179 test rows (an 80/20 split, fixed seed, identical across every model in this report so accuracy numbers are directly comparable). The five classes are close to perfectly balanced, roughly 20% each, even though Carpineti et al.'s original raw collection was substantially imbalanced (26% Walking, 25% Car, 24% Still, 20% Train, only 5% Bus, a realistic reflection of actual usage frequency, not a collection error). The publicly distributed \(D_3\) file has already been rebalanced by an undocumented procedure before we ever touched it, so every accuracy number in this report measures discrimination between five equally likely classes, not real-world deployment accuracy where Bus trips are genuinely rarer.

A simple correlation motivates why feature selection is a meaningful question at all: `accelerometer.mean` and `linear_acceleration.mean`, two sensors measuring closely related physical quantities, correlate at 0.557. With 36 features built from only nine underlying physical sensors, this kind of overlap is the rule, not the exception.

Several methods used later in this report, PCA, PCR, PLS-DA, implicitly rely on roughly-normal, roughly-linear structure; the tree-based methods make no such assumption. We checked which assumption the data actually supports rather than inferring it after the fact from which methods won: all 36 of 36 features reject normality under an Anderson-Darling test, confirmed by Shapiro-Wilk on a random 5,000-row subsample. Most features are strongly right-skewed, a mass of near-zero readings with a long tail, as the figure below shows for the single worst-fitting feature.

![Histogram of speed.std zoomed to its 99th percentile, against its best-fit normal curve](/images/research/transportation-mode-detection/speed_std_normality.png)

*`speed.std`, the worst-fitting feature by skewness, plotted against the normal curve with the same mean and standard deviation. The extreme right tail beyond the 99th percentile, cut off here for readability, is why this feature fails normality so badly. Full per-feature diagnostics for all 36 features are in the project's `distribution_check.R`.*

## Literature review

Carpineti et al.'s (2018) original study, titled *Custom Dual Transportation Mode Detection by Smartphone Devices Exploiting Sensor Diversity*, was built on the premise that no single smartphone sensor reliably identifies transportation mode alone, so combining several is necessary. Our finding that the 36 features are substantially redundant is, in a sense, the flip side of that premise: deliberately overlapping measurements produce exactly the redundancy we later measure. Zhu et al. (2016), using a different but related smartphone dataset, independently report the same confusion pattern we find in our own clustering work below, that "the behaviors of the car-bus and the train-metro are very similar, making mode classification difficult," with bus-to-car confusion up to 11.27% under k-nearest-neighbors, corroborating evidence from a different group with different sensors and participants.

The six feature-selection methods span two philosophically different goals Kursa and Rudnicki (2010) distinguish in introducing Boruta: all-relevant selection ("which features carry any signal, however small or duplicated") versus minimal-optimal selection ("what is the smallest feature set achieving peak performance"). Boruta answers the first, recursive feature elimination the second, which is why Boruta confirming all 36 features and RFE narrowing to 14 are complementary answers to different questions, not contradictory ones. Guyon et al. (2002), who introduced RFE for a small-n, large-p gene-expression problem using a linear SVM ranking model, is a procedure we borrow while substituting a Random Forest, a substitution we flag rather than present as a like-for-like replication given our data sits in the opposite regime (roughly 4,700 rows against 36 features). Strobl et al. (2007) motivates conditional permutation importance as a sixth, stricter check: ordinary Random Forest importance is systematically biased upward for correlated features, since scrambling one member of a correlated cluster still lets the model exploit its near-duplicate partners.

On the classification side, Barker and Rayens (2003) formalized Partial Least Squares Discriminant Analysis, which originates in chemometrics and constructs components efficiently from few observations, unlike PCA/PCR's variance-only criterion. Grinsztajn, Oyallon, and Varoquaux (2022) benchmarked tree-based models against deep learning across 45 tabular datasets and found trees remain state-of-the-art at medium scale, around 10,000 rows, close to this project's 5,893, attributing this to robustness to uninformative features and insensitivity to feature-axis rotation. That rotation point connects directly to our own Research Question 2 results: PCA, PCR, and PLS-DA all impose a single, fixed rotation of the 36-dimensional space before classification, exactly the transformation Grinsztajn et al. identify tree-based methods as gaining nothing from, consistent with every tree-based method outperforming every rotation-based linear method here. Kittler et al. (1998) prove that simple sum/average combination is the most robust fixed rule for combining classifiers' probabilities, matching our own finding that a weighted Random Forest/XGBoost blend, swept across every mixing ratio, could not reliably beat simple 50/50 averaging by more than sampling noise.

## Models

We use six complementary feature-selection approaches, each answering a subtly different question. One-way ANOVA per feature, \(X_{ij} = \mu + \tau_k + \epsilon_i\), tests whether each feature's mean differs across the five classes: all 36 of 36 features are significant at \(p < 0.05\), establishing that essentially none of the 36 is pure noise, without yet establishing that all 36 carry unique, non-redundant information. Unsupervised PCA, the leading eigenvector of the standardized covariance matrix and each subsequent orthogonal component, finds that only 12 of 36 components are needed to capture 90% of total variance, direct evidence of redundancy. Multinomial LASSO with a grouped \(L_1\) penalty, \(P(Y=k\mid X)\propto\exp(\beta_{0k}+X\beta_k)\) with \(\lambda\sum_{j=1}^{36}\lVert\beta_j\rVert_2\), selected by 10-fold cross-validation, keeps 30 of 36 features at \(\lambda_{\min}\), dropping `game_rotation_vector.mean`, `linear_acceleration.min`, `orientation.mean`, `rotation_vector.mean`, `sound.max`, and `sound.mean`. Boruta, pairing every feature with a shuffled shadow copy and testing whether the real feature beats the best shadow across 200 runs, confirms all 36 as distinguishable from noise, again telling us what's not redundant with noise rather than what's redundant with each other.

Recursive Feature Elimination, repeatedly dropping the least important feature by out-of-bag Random Forest accuracy and refitting (\(\texttt{ntree}=300\), chosen after a direct sweep from 10 to 1,000 trees showed out-of-bag error flattening by roughly 100), is the one method that directly measures predictive accuracy rather than a proxy for it: accuracy peaks at 14 features (95.31% out-of-sample), then declines sharply below 8 to 10. Conditional permutation importance (Strobl et al., 2007), correcting ordinary Random Forest importance for correlation bias by permuting each feature only within its correlated partners' subgroups, is far stricter: only `sound.std`, `sound.min`, `accelerometer.std`, `sound.mean`, and `sound.max` register any importance above zero. This is a diagnostic result, not a standalone selection recommendation: a Random Forest trained on only these five achieved just 76.17% test accuracy, since removing every individually-redundant feature at once removes the redundancy itself, a fundamentally different scenario from removing features one at a time while correlated backups remain.

Nine classification approaches are then compared on the identical training and test split. A classification tree, grown to entirety (398 leaves) and cost-complexity pruned by 10-fold cross-validation down to 172 leaves, raises test accuracy from 73.96% (`rpart`'s untuned default) to 89.14%, a controlled demonstration of the cost of an untuned default. Random Forest, bagging many unpruned trees and additionally restricting each split to \(\texttt{mtry}=\lfloor\sqrt{p}\rfloor\) random candidate features to decorrelate the ensemble, is compared across three feature sets under an identical specification: 86.01% on 9 hand-picked features, 95.42% on the RFE-selected 14, 95.17% on all 36. Principal Component Regression adapts PCA to a categorical outcome via multinomial logistic regression on the top \(M\) components, with \(M\) chosen by 5-fold cross-validation over \(M \in \{2,5,8,10,12,15,20,25,30,36\}\); cross-validated accuracy climbed monotonically across the entire grid rather than peaking at an intermediate value, so the tuning procedure itself selected \(M=36\), essentially no real dimensionality reduction, reaching 72.77% test accuracy. PLS-DA, building each component to maximize covariance with a dummy-coded response rather than blind variance, peaks at \(M=10\) and declines slightly beyond it, a genuine elbow unlike PCR's monotonic climb, reaching 65.31%.

XGBoost, gradient boosting sequential trees against the gradient of multinomial log loss (`max_depth=4`, `eta=0.1`), had its boosting-round count selected by a held-out validation set (497 of a 500 maximum), then refit from scratch on the complete training set at that round count, reaching 97.29% test accuracy, the best of any method attempted. A cascaded (hierarchical) classifier first collapses the problem to three classes (Still, Vehicle, Walking, merging Bus/Car/Train), routes rows predicted "Vehicle" to a second, independently-tuned XGBoost stage for the Bus/Car/Train decision, and reaches 96.52%, targeting the specific confusion identified in the clustering work below. An ensemble, averaging Random Forest's and XGBoost's predicted class probabilities element-wise following Kittler et al.'s (1998) sum rule, reaches 97.20%; a supplementary sweep of non-50/50 blending ratios did not improve on simple averaging beyond sampling noise.

## Backtesting

Every model in this report is evaluated once, on an identical, untouched test set, never re-used for tuning. But the more consequential validation question this project ran into wasn't which model wins, it was whether the winning number could be trusted at all.

RQ2's headline result exists only because of a bug caught live mid-project: three separately hand-written XGBoost scripts had each fit their *final* model on the validation-excluded subset used only to pick the number of boosting rounds, never refitting on the full training set afterward. This produced a completely plausible number, 95.93%, that didn't announce itself as wrong the way an earlier, unrelated reshape bug had (an obviously broken ~19% accuracy). It surfaced only because a fourth, independently-written ensemble script's own XGBoost block disagreed with the figure the whole project had been citing as the benchmark. An audit across every XGBoost fit in the project found the bug lived in copy-pasted logic, not a random one-off mistake: the cascade and ensemble scripts, which had each written their own full-refit logic from scratch, were already correct, while three separately hand-written flat-XGBoost scripts shared the identical error. The corrected accuracy, 97.29% up from 95.93%, is what every number in this report reflects; the RFE-14 model carried the same gap in miniature, 95.42% to 95.76% once refit correctly, and an already-written conclusion that the 14-feature model "nearly matches" the full model had to be walked back once both were refit honestly, from a 0.5-point gap to the real 1.53-point gap.

We also ran the equivalent of the "should we use a more complex model instead" test this site's other pages ask of themselves. Every one of the 36 raw features is non-Gaussian, several severely, yet ordinary PCA is built entirely around the covariance matrix, a second-moment summary blind to that skewness. Huang, Lu, and Boudt's (2026) Higher-order multi-cumulant Factor Analysis (HFA) replaces the covariance matrix with one built from third- or fourth-order cumulants specifically to recover factors that are weak in variance but genuinely non-Gaussian. Using the authors' own vendored R implementation on our standardized features, both their GER3 and GER4 rules for choosing the number of factors agreed on \(R^*=2\). Before trusting that estimate, their method requires the residuals left after removing the factors to be Gaussian, a check that holds almost exactly on the paper's own validation data (2.4% and 1.61% rejection); on ours, it does not, 100% of our 36 residual series still reject normality under both orders. We report the HFA comparison below as descriptive and exploratory rather than backed by the paper's asymptotic theory, precisely because that assumption fails here.

![Top three levels of the pruned classification tree, illustrative](/images/research/transportation-mode-detection/tree_plot.png)

*The full tuned tree has 172 leaves; only its top three levels are shown here for readability. The root splits first on low `linear_acceleration.mean` (isolating Still and Car), and within that, high `accelerometer.std` separates Bus from Car, a readable illustration of how the tree-based methods actually carve up the space that the linear methods above cannot.*

Every classifier in this report makes most of its errors confusing Bus, Car, and Train with each other, while Walking and Still are classified nearly perfectly. Hierarchical clustering on the five true class centroids in standardized sensor space shows Walking sitting two to three times farther from every other class than those classes sit from one another, with Bus and Train the single closest pair of all, a direct, quantified, model-independent explanation for the recurring confusion: it reflects genuine geometric closeness of these classes' sensor signatures, not a weakness of any particular classifier. A complementary, purely unsupervised k-means elbow sweep across the raw 36 features shows no sharp elbow at K=5, the true number of classes, within-cluster variance instead declining smoothly and only tapering around K=4.

![Scree comparison: ordinary PCA against HFA3 and HFA4, cumulant-based factor extraction](/images/research/transportation-mode-detection/hfa_scree_comparison.png)

*PCA's gently declining curve against HFA3/HFA4's sharp single-factor drop, the same "one strong factor, then a cliff" pattern the original HFA paper reports on its own FRED-MD macroeconomic data. At the matched \(R^*=2\) components, HFA3 reaches 51.48% test accuracy against 41.82% for ordinary PCA, a statistically significant gap by McNemar's test, consistent with the paper's central claim, though both remain far below this project's actual recommended method (XGBoost, 97.29%), since a handful of factors cannot capture what a full nonlinear model does.*

![Unsupervised clustering purity restricted to Bus, Car, and Train, raw features versus PCA versus HFA3](/images/research/transportation-mode-detection/vehicle_hfa_clustering.png)

*Restricted specifically to the Bus/Car/Train confusion, all three representations land at statistically indistinguishable purity (raw 0.4481, PCA 0.4392, HFA3 0.4403, all well above the 0.33 random floor but far from clean separation): HFA finds no hidden structure here that raw features or PCA don't already show. This sharpens rather than contradicts the scree comparison above, its accuracy gain there most plausibly came from separating the easy classes (Walking, Still), not from resolving Bus/Car/Train, which stays just as unresolved under a cumulant-based representation as a covariance-based one, and is the direct justification for why the method that actually improved on it, the cascaded classifier, had to be nonlinear and supervised rather than a smarter unsupervised representation.*

### What this doesn't show

This dataset carries no user or session identifier, so we cannot fully rule out some inflation of test accuracy from within-session correlation between train and test rows, a documented risk for this class of problem in the broader trajectory-classification literature. The conditional permutation importance diagnostic was too computationally expensive, roughly 25 to 30 minutes per run, to re-run repeatedly during development, so it is reported from a single verified run rather than recomputed alongside every other result. And the HFA comparison, however suggestive, rests on a Gaussian-residual assumption this data does not satisfy, which is exactly why it's reported here as descriptive rather than as a competing recommendation for Research Question 2.

## Conclusion

Six independent feature-selection methods and nine classification approaches, evaluated on an identical train/test split, tell one consistent story rather than two separate ones. The 36 raw sensor features are substantially redundant rather than individually useless, `sound`- and `accelerometer`-derived features are the most consistently important, and a 14-feature subset recovers essentially all achievable accuracy, confirmed independently by both Random Forest and XGBoost. That same redundant, non-Gaussian structure explains why every tree-based method outperforms every linear method by 25 to 30 percentage points: PCA, PCR, and PLS-DA all impose a fixed linear rotation that this problem's non-linear class boundaries cannot be captured through. A correctly-tuned XGBoost model, refit on the complete training set after hyperparameter selection, reaches the best test accuracy of any method attempted, 97.29%, precisely because it needed no such rotation, and that number is trustworthy specifically because a live, self-caught methodology bug was found and corrected before it shipped, not because the first number that came out looked good.

The more transferable finding is methodological rather than dataset-specific: redundancy and non-linearity are not independent properties to be discovered by trial and error across nine models, but a single diagnosis that, once made cheaply (how many components for a given variance target, whether the raw features are Gaussian), predicts up front whether linear dimension reduction is worth trying at all or whether effort is better spent tuning a tree-based model directly.
